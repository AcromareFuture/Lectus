## 独立校验与上架缺口

- 压缩包 CRC 检查通过，无重复成员名和本次规则检出的危险相对路径。SQLite `integrity_check` 为 ok、`foreign_key_check` 无结果；JSON 与 SQLite 六表记录数一致，主键无重复，检查的外键目标均存在。
- 1,164 张商品图全部实际解码成功，尺寸均为 1200×1200，与台账 SHA-256 一致，无缺失文件。448 张来源短边小于 1200，输出画布不代表原始清晰度达到 1200。
- 11 个重复图片文件可以按内容哈希复用；1,153 个唯一内容约 184.9 MiB，当前去重节省有限。
- 12 个 SPU、91 条配色记录、110 个 SKU 没有主图；这些记录可以进入待完善区，不能借用其他颜色图片冒充完整商品。
- 2,732 条来源价格都有 amount，但币种全部为空。52 个 SPU 的来源 SKU 金额不一致，不能直接套用当前 SPU 单价或当成人民币销售价。
- 没有本方可售库存数量字段。1,917 条 source_available=true、815 条 false 仅代表采集时来源状态，不能作为本方库存数量。
- 562 个 SKU 有两维或三维 specs；涉及 Size、Type、Switches、Switch Type、Model、Backlight、Sensor、Shade、Finish 等字段。不能只映射为尺码、颜色，也不能从所有选项生成笛卡尔积。
- 43 条配色未明确标色，不能将 876 条配色记录都当作已核实颜色。鞋码单位及单位换算也需保留来源信息。
- 5 条关联跨越台账的配色 ID，均未跨 SPU：3 条为 Lemokey 同款键盘 Cyber 与 ISO-DE/ISO-UK/ISO-Nordic 布局共图；另 2 条涉及粉底色号及润唇膏/组合，需要复核共享图片依据。不能仅因有外键就判定图片映射正确。
- 来源可追溯，但图片使用授权、来源采集可售状态和本方经营信息仍需分别确认。工程接入估算不包含人工核价、补图及授权处理。

建议第一步全部导入待审核商品库，保留原始价格、币种空值和来源状态；缺图或待定价记录有明确状态，确认人民币售价、本方库存等经营字段后再允许交易。

## 必需的本地代码改造

1. **MySQL 适配**：当前 pom 只有 H2/PostgreSQL 驱动和对应 Flyway 支持；补 MySQL 依赖、时区/时间列迁移和实际 MySQL 集成验收。`CatalogService` 搜索使用 `||` 字符串连接，需改为 MySQL 兼容写法。不能仅替换 JDBC URL 就上线。
2. **商品模型**：保留品牌、SPU、配色、SKU、图片、SKU 图片关系；增加多维规格、来源记录、上架状态、SKU 级售价与库存。源数据与本方经营字段分开，现有账号、订单快照不被导入覆盖。
3. **可重复导入**：按稳定 ID 幂等写入，支持 dry-run、批次记录、异常清单、图片哈希校验、失败重试与限定批次回滚；不重复上传相同素材，不把候选索引当成交付商品。
4. **素材服务**：在现有 MinIO 建莱择独立素材空间及应用权限，生成列表缩略图与详情图；保留对象版本/内容哈希，供浏览器缓存。原始 ZIP、采集缓存及工具不进入公开商品素材目录。
5. **前端接口联调**：主商城目前仍以 src/data.js 和本机状态为主，真实服务端流程位于账号页。接入分页、分类/品牌筛选、真实图库、配色切图、动态 SKU 规格和缺图/待定价状态；迁移与旧演示记录保持兼容。
6. **Redis 和上线验证**：为商品数据配置莱择专属键空间、TTL 和更新失效规则，数据库继续作为价格、库存、订单的依据。现有 Redis 是共享环境，不直接修改全局淘汰参数；独立实例或 ACL/容量隔离需在部署方案中明确。接入 Java 服务、Nginx API 转发、健康检查和回退路径。

建议隔离资源命名：MySQL `lectus` 和专用应用账号；MinIO `lectus-assets` 和对应服务账号；Redis `lectus:*`。这是待实施设计，本轮尚未创建。运行时不使用 MySQL root。
